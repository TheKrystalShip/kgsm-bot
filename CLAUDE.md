# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`kgsm-bot` is the **Discord surface onto KGSM** — one of the `kgsm-*` leaves in the `tks` umbrella
workspace. It is a **leaf consumer**: it reaches the engine only through `kgsm-lib`, never by shelling
`kgsm.sh` itself. Its conversational half is a **client of the kgsm-assistant leaf** — one engine
behind every surface, so a chat held here is the same conversation the Control Panel and the
assistant's own site show. The workspace root `../CLAUDE.md` + `../system-architecture.md` carry the
ecosystem rules this repo inherits, including the documentation canon.

**Subsystem rules live in a `CLAUDE.md` beside the code they govern**:
`src/KGSM.Bot.Discord/` (listeners, the @-mention surface) with `Commands/` (gating, stage→confirm,
`/setup`, the command manifest) and `Voice/`; `src/KGSM.Bot.Infrastructure/` `KGSM/` (events, cache,
rosters, backups, history, `/connect`), `Discord/` (announcing, the board, presence, health, the send
queue), `Authorization/`, `Guilds/` and `Speech/`.

## Building

This repo builds standalone — every dependency is a package from the org's GitHub Packages feed
(`nuget.config`). `TheKrystalShip.KGSM.Lib` is pinned by version in Core, Application and
Infrastructure, and the three pins move together; the same bump → publish → re-pin loop applies to
`TheKrystalShip.Kgsm.Assistant.Relay` (the assistant's per-turn contract),
`TheKrystalShip.KGSM.Cluster` (membership, and the token this bot calls the assistant with) and
`TheKrystalShip.KGSM.Auth`.

```bash
dotnet build kgsm-bot.sln
dotnet test  kgsm-bot.sln --filter "FullyQualifiedName~ConfirmationIds"   # one class/test
cd src/KGSM.Bot.Discord && dotnet run        # run locally (reads kgsm-bot.settings.json)
```

`deploy/deploy.sh` publishes a **framework-dependent single-file** binary (the host must have the
.NET 10 runtime) into `/opt/kgsm-bot`. Neither deploy script overwrites the live env file, so the
Discord token (`/etc/kgsm-bot/kgsm-bot.env`) survives provisioning and every redeploy.

Tests (`tests/KGSM.Bot.Core.Tests`, xUnit + NSubstitute + FluentAssertions, mirroring the source
layout) mock at the `IServerInstanceService`/`IMediator`/cache seams and at the assistant client's HTTP
transport; there is no live Discord, kgsm or assistant in the suite.

## Configuration

`src/KGSM.Bot.Discord/kgsm-bot.settings.json` declares the bot's **whole** configurable surface with
its defaults, and is committed — it holds no secret and names no Discord server. An environment
variable **overrides one key** of that file by spelling the key's path with `__` (`Discord__Token`),
and a variable naming a key the file does not declare binds to nothing.

**`deploy/kgsm-bot.leaf.json` is generated, not written.** `TheKrystalShip.KGSM.ComponentConfig`
rewrites it on every build from `[ConfigField]` attributes and `<panel>` doc tags on the options types
in `KGSM.Bot.Infrastructure/Configuration` — so edit the options classes, never the JSON, and commit
what the build produces. The build fails when the settings file and the annotated options classes
disagree in either direction.

## Architecture

Clean Architecture: `Discord → Infrastructure → Application → Core`; Core depends only on `kgsm-lib`
models + logging abstractions. Application is the **MediatR** layer (`ServerCommands.cs`,
`ServerQueries.cs`, `ServerEventCoordinatorService`, which wires kgsm events → Discord announcements +
cache invalidation); Infrastructure holds every implementation and all DI wiring
(`DependencyInjection.cs`).

**Two surfaces, one execution path.** Everything that mutates a server funnels through the same
MediatR pipeline (`IMediator.Send` → handler → `IServerInstanceService` → `kgsm-lib`), whether a slash
command or the assistant triggered it.

**Provenance.** `Core/Common/InvocationContext.cs` is an `AsyncLocal`-backed ambient holder; entry
points call `_invocation.Begin(Invocation.ForDiscordUser(username))` and the kgsm chokepoint stamps
`actor`/`origin` from it. **When adding a new mutating entry point, wrap it in a `Begin(...)` scope.**

**Two names: the id it is keyed by, the label it is called.** A server's **id** is generated by the
engine at install, immutable, and what the guild store, the channel bindings, the follow filter, every
slash-command argument and every event payload key on; its **display name** is free text that changes
whenever somebody likes. `ServerLabel` is the one place the two are composed. Shown by label, keyed by
id, everywhere; a missing label is the id, never an invented one.

**Everything the bot says unprompted goes through `IDiscordSendQueue`.** A new outbound call belongs
there too; a direct `SendMessageAsync` off the client is a producer nothing paces. Interaction replies
are the exception and must stay out of it.

## Ecosystem invariants that bite here

- **Never fabricate a status.** An unreadable instance is reported as unavailable with the reason,
  never as a fake `stopped`, and a run state that could not be read is reported as unread.
- **Degrade gracefully when a dependency is absent.** The watchdog, the assistant, the firewall
  authority and the `kgsm-speech` leaf are each optional, and each absence costs only the piece that
  reads it. Ports open when a server starts and close when it stops — the watchdog's and the
  firewall authority's business, never a chat surface's.

## Version tracking

- **Version source:** `<Version>` in `src/KGSM.Bot.Discord/KGSM.Bot.Discord.csproj` — the deployable;
  the Core/Application/Infrastructure libraries carry none.
- **Packaging reads it via `deploy/version.sh`** — `./deploy/version.sh` prints the declared version,
  `--pkgver` prints the pacman-safe form. A package never restates a version number; it asks for one.
- Bump the version whenever you make a user-facing change (patch for fixes, minor for features, major
  for breaking changes), with a `CHANGELOG.md` entry under `## [Unreleased]`.
